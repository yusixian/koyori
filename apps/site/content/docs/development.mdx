## 环境

- Node.js 22.23.2
- pnpm 10.28.2
- macOS（桌面应用的首要开发与验收平台）

仓库根 `package.json` 是产品版本的唯一来源。工作区内的私有包使用自己的内部包版本，不代表 Koyori 发布版本。

## 启动桌面应用

```bash
pnpm dev
```

Electron 开发窗口的本机页面从 `http://localhost:15173` 开始；若已被占用，Vite 会选择后续可用端口，并在终端显示实际地址。打包后的桌面应用不监听这个端口。

## 启动文档站

```bash
corepack enable
pnpm install
pnpm dev:site
```

文档站默认监听 `http://localhost:5174`。

## 相关检查

```bash
pnpm --filter @koyori/site typecheck
pnpm --filter @koyori/site build
```

开发时先运行与改动相关的检查；全量检查由 CI 承担。命令结果只能证明对应检查通过，不能替代安装包、部署环境或真实外部服务验收。

## 内容边界

站点只发布 `apps/site/content/docs` 下明确加入的内容，以及从 `docs/releases/unreleased.md` 或对应版本的 `docs/releases/v<VERSION>.md` 同步生成的更新页。只有 `apps/site/public/releases/preview-mac-arm64.json` 经过核心清单校验时，下载页才显示公开安装包；不能仅因为仓库里有版本正文就宣称已经发布。不要将凭据、真实会话、个人路径或服务器信息放进公开内容与 fixture。

公开 Preview Release 后，维护者可运行 `pnpm --filter @koyori/site promote:release --tag v<VERSION>`。命令从 GitHub Release 下载并核验完整发行资产，再更新仓库内的站点清单；还需将清单合入站点分支、部署并核对公网下载页与文件摘要。具体操作见 [macOS 签名与发布](https://github.com/yusixian/koyori/blob/main/docs/release-signing.md)。
