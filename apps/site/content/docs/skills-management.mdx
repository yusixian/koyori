---
title: Skills 发现、同步与备份
description: 自动发现 Claude Code 与 Codex Skills，预览同步，并用本地快照安全恢复。
---

Koyori 会自动检查 Claude Code 与 Codex 的常用 Skills 目录。发现只建立清单，不会复制、启用、上传或运行 Skill。你仍然可以添加自定义目录，或登记一个项目来查看项目级 Skills。

## 自动发现哪些目录

| 客户端 | 用户目录 | 登记项目后 |
| --- | --- | --- |
| Claude Code | `$CLAUDE_CONFIG_DIR/skills`；未设置时为 `~/.claude/skills` | `<项目>/.claude/skills` |
| Codex | `~/.agents/skills`，以及兼容目录 `$CODEX_HOME/skills`；未设置时为 `~/.codex/skills` | `<项目>/.agents/skills` |

Codex 系统目录 `/etc/codex/skills` 只作为只读来源。项目目录也只在你明确登记项目后检查；Koyori 不搜索整块磁盘。相同实际目录会按规范路径去重，链接仍会显示提示。

在资源清单中打开“添加来源”，可以暂停自动发现、重新检测、恢复曾忽略的来源或添加项目。移除来源只断开 Koyori 的登记，原文件不会被删除。应用启动后会先检测一次，运行期间每 30 秒检查新增和变更；忙碌中的写入或导入不会被定时检查打断。

## 从 Claude Code 同步到 Codex

1. 在资源清单选择一个或多个 Skills。
2. 打开“同步与备份”，选择 Codex 目标。
3. 先查看计划中的来源、目标、文件数、大小、动作和兼容性提示。
4. 内容不同会显示冲突。只有明确选择替换并重新生成计划，才会允许执行。
5. 执行完成后重新扫描，确认目标清单已经更新。

同步复制完整目录，包括 `SKILL.md`、脚本、引用文件和素材，并保留文件执行位。来源原件不会被修改。同内容目标直接跳过；目标在预览后发生变化，或被链接接管时，执行会停止并记录失败。目录中的链接只有在解析后仍位于已授权目录内才会读取，复制结果是实际内容，不会把跨界链接带到目标。

Claude Code 的 `allowed-tools`、`context` 等专用 frontmatter 会显示兼容性提示。提示表示需要人工核对目标客户端行为，不代表 Koyori 已经转换或验证这些字段。

## 部署到已登记项目

在资源清单中先登记项目，再选中一项 Skill，打开“同步与备份”里的“部署到项目”。选择该项目的 Claude Code 或 Codex 目标，预览来源、目标、文件数和兼容性提示，确认后才会复制完整目录。已有同名目标即使内容相同也不会被 Koyori 接管或替换。一次只部署一项，来源保持原样。

“受管项目副本”列出 Koyori 完成并登记的部署。撤销前会重新检查目标内容；如果文件被外部修改、目标已断开或项目不再登记，撤销会停止。成功撤销会把该副本移到 Koyori 应用数据目录的恢复材料中，保留操作记录，不删除来源。中断时按操作记录显示的位置人工核对。

**撤销项目副本不等于隐藏全局 Skill。** 如果来源仍在客户端扫描的用户级或共享目录，它可能继续可见；Koyori 不据此推断客户端会话中的实际加载状态。CLI 的 `sync` 不建立受管项目部署记录；请使用下面的 `project-deploy` 来建立可撤销的受管副本。

## 本地快照与恢复

“备份所选 Skills”会把选中 Skill 的完整目录保存在 Koyori 应用数据中。替换已有目标前也会自动创建写前快照。快照与原 Skills 分开保存；它们是恢复材料，不是可随意清理的缓存。

恢复仍会先生成计划。目标内容与快照不同，需要明确选择替换；预览后发生的外部编辑会阻止覆盖。多项恢复会逐项记录成功、失败、取消或中断，因此部分成功不会显示成全部完成。

替换时，实际被移走的原目录也会保留。可在“最近文件操作”查看结果和恢复材料路径；进程中断后记录会标为中断，并列出可能的存放位置，供人工核对恢复。Koyori 不会在重启时自动覆盖目标，也不会把这些材料当缓存清理。

从其他设备导入的便携快照不会带入原机器的绝对路径。恢复这类快照时必须选择 Claude Code 或 Codex 目标，Koyori 使用快照保存的目录名建立目标，不会猜测原位置。

## 保存到 Git 远端

在“同步与备份”底部连接自己的备份仓库。连接不会上传 Skill，也不会修改客户端目录。建议使用专门的私有仓库和已配置的 SSH 身份。HTTPS 当前只支持无需认证的远端；地址中不要填写密码或 Token。

1. 先在本机备份选中的 Skills。
2. 连接远端，选择要上传的本地快照，核对其中资源并确认目录内容。
3. 上传完成后查看“远端已核验”和提交摘要。只有确认远端分支与上传提交一致才会显示这一状态。
4. 在“远端历史”取回快照。取回只导入本地快照库；需要恢复文件时，再选择客户端并预览恢复计划。

本地已保存、等待上传、上传失败、远端待核验和已核验会分别显示。离线或推送失败时，本地快照仍保留；修复连接后可以重新上传。远端出现不同历史时拒绝强制覆盖。断开远端会暂停自动备份，并保留本地恢复材料。

已有提交的备份库会绑定原远端；断开后可以重新连接同一地址，当前不能直接换成另一个仓库。这避免把原仓库的历史文件随新快照一起传给其他远端。含嵌套 `.git` 目录的 Skill 会明确拒绝上传，请先检查该目录是否属于需要备份的内容。

**自动备份默认关闭。** 明确选择资源并启用后，应用运行期间监听这些目录；变更平稳两分钟后创建本地快照并尝试上传，失败逐步延后重试，最长间隔一小时。重启会补检查；应用退出后不继续联网上传。新发现的其他 Skills 不会自动加入上传范围，断开资源来源会停止读取。

便携快照只包含所选 Skill 的完整文件、相对目录清单和 SHA-256 摘要。客户端原始会话、使用账本、来源设置与原机器路径不随快照上传。**自行写在 Skill 正文、脚本或附属文件中的敏感内容仍属于上传文件**，Koyori 不声称能自动识别这些内容。

Git 备份已经通过隔离的本地 bare 仓库往返测试。SSH/HTTPS 的实际可用性还取决于你本机的 Git、身份配置和远端权限；本项目测试不会替你上传真实个人 Skills。

## CLI 预览与执行

CLI 与桌面端共用发现、计划、revision 检查、快照和恢复核心。以下路径仅作结构示例，请替换为你明确授权的目录：

```sh
pnpm koyori discover

pnpm koyori sync \
  --source ./claude-skills/example \
  --target ./codex-skills/example \
  --from claude-code --to codex \
  --root ./claude-skills --root ./codex-skills \
  --store ./koyori-data
```

`sync` 和 `restore` 第一次只输出计划和 revision。检查 JSON 后，以同样参数追加 `--apply <revision>`；Koyori 会重新生成计划，文件或选项变化会使旧 revision 失效。替换现有不同内容时，还需在预览和执行两次命令中都加入 `--replace`。

项目级部署同样先预览，且需要显式指定项目、来源目录、来源与目标客户端、授权根和本地数据目录。目标目录由项目与目标客户端确定，Codex 使用 `<项目>/.agents/skills/<Skill 目录名>`，Claude Code 使用 `<项目>/.claude/skills/<Skill 目录名>`：

```sh
pnpm koyori project-deploy \
  --project ./my-project --source ./claude-skills/example \
  --from claude-code --to codex \
  --root ./claude-skills --root ./my-project/.agents/skills \
  --store ./koyori-data
```

核对输出的 `plan`（尤其是 `targetPath`、`conflict` 和兼容性提示）后，以完全相同的参数追加 `--apply <revision>`。CLI 会在新进程重新生成计划并比较稳定摘要，再调用核心执行；计划 ID 本身不能跨进程使用。已有目标即使内容相同也不能接管，项目部署没有 `--replace`。部署成功的 JSON 包含 `operation` 与带 ID 的 `deployment`；`project-deployments --store ./koyori-data` 可列出记录。

撤销使用登记的部署 ID、同一个 `--store`、明确的项目和覆盖该项目 Skills 目录的授权根：

```sh
pnpm koyori project-revoke \
  --project ./my-project --deployment <deployment-id> \
  --root ./my-project/.agents/skills --store ./koyori-data
```

先核对撤销计划，再以同参数追加 `--apply <revision>`。目标被外部修改时计划会显示冲突，撤销不会执行；成功后输出的 `deployment.recoveryPath` 是保留的副本位置。CLI 用显式项目路径授权本次操作，不会自动替你在桌面端登记项目。若需桌面端查看同一批部署记录，使用桌面端的数据目录作为 `--store`，并在桌面端登记该项目。

```sh
pnpm koyori backup \
  --source ./claude-skills/example \
  --root ./claude-skills \
  --store ./koyori-data

pnpm koyori backups --store ./koyori-data

pnpm koyori restore \
  --snapshot <snapshot-id> \
  --target ./codex-skills \
  --root ./codex-skills \
  --store ./koyori-data
```

CLI 的 `backup` 当前只创建本地快照。`--root` 是本次进程可以读取或写入的目录边界；它不会授权边界外的链接目标。退出码 `0` 表示计划可执行或执行成功，`1` 表示冲突或操作失败，`2` 表示参数错误或预览后内容与参数变化。计划、操作及错误均以 JSON 输出。
