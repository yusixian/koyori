# cos-tool-bot 参考实践与 Koyori 适配

> 2026-09-22；工程实践参考。仅记录公开设计原则，未复制私有实现。

## 参考范围

参考维护者已有项目的公开文档实践与工程经验，只记录可公开的设计原则。私有仓库的提交、内部文件路径、实现细节、配置及数据不包含在本文，也未被移植到 Koyori。

重点是独立文档构建、发布说明单一来源、隔离验收、Provider 连接与任务选择分离，以及 API、业务服务、持久化的后端分层。参考经验不代表 Koyori 已完成实现或验证。统一域名、后端选型、首个桌面通道和上线边界见 [后端方案](backend.md)。

## 优先借鉴

### 文档与发布

采用“一份发布正文、多个出口”：`docs/releases/vX.Y.Z.md` 同时供文档站与 GitHub Release 使用；未发布草稿单列，不污染历史说明。版本页标题使用版本号、主题作副标题，内容包含功能、修复、升级/迁移、限制与验证范围。版本索引需要与正文集合一致，不能新增版本后忘记导航。

Koyori 已采用 Fumadocs + React Router 预渲染，并通过独立站点镜像部署到 Dokploy。参考项目把静态文件放在 Hono 的 `/docs` 下；Koyori 保留站点独立部署，后续 API 通过同一域名的专用路径接入。

沿用独立、无需业务数据库与凭据的文档开发方式。公开目录显式选择，安装/下载/版本说明匿名可访问；检查深层地址刷新、搜索、移动导航、404、旧版本 URL。GitHub Release 已发布、文档已构建、Dokploy 已部署、公开页面已核验分别报告。

### Agent 开发约定与验收

借鉴真实仓库地图、实际脚本和领域边界的写法。Koyori 已建立自己的 package.json 与实际检查命令，见 CONTRIBUTING.md；不能复制参考命令冒充本项目的验证。

验收使用隔离数据、固定场景、步骤与预期、截图和可追溯报告；本地日常按变更范围运行。桌面程序另需安装包、系统权限、退出重开和升级验证，不能用 Web 浏览器验收代替。证据绑定候选 commit/产物，避免把别的分支或旧版本结果当成当前门禁。

## AI Provider：可借鉴的模型与新增候选

Provider 是连接配置，模型是该连接上的可用目录，任务选择决定本次实际使用哪个模型，运行时负责调用、取消和统计。参考项目 UI 明确区分正在编辑的 Provider 与默认生效 Provider；Koyori 应保留这种分离，避免查看另一个连接就改变后台任务。

Koyori 的起步候选流程：添加连接 → 配置地址和凭据 → 手动添加模型或主动发现 → 用固定最小输入测试 → 选择为某类任务的默认值。先接通一种真实需要的 API 协议，再扩展其他协议；API Key 与本地 ACP 是不同适配入口，不把 MCP 或 ACP 当成任意模型 API 的替代品。

- 持久配置只保存凭据引用，界面返回“已配置”而非密钥。参考项目的服务器加密数据库方案需适配为桌面系统安全存储，不复制部署环境密钥到客户端。
- 模型列表来自服务不代表每个模型都支持图像、工具或结构化输出；能力须区分声明、人工配置和测试观察。发现失败允许手动添加，不能顺便切换运行模型。
- 测试区分地址可达、模型列表读取成功与实际推理成功。推理测试可能付费，明确触发、固定最小输入，不自动发送私人项目内容。
- 本地/自建服务地址是合法需求，但需用户显式配置。约束发现路径、重定向、响应大小和超时，阻止云元数据目标及凭据意外转发；更换目标地址时重新确认凭据适用范围。
- 任务启动记录所选连接/模型及非敏感配置版本；运行中修改默认值不静默改变现有任务。取消和超时真实传到适配器；失败不自动转发到另一个未授权的服务。
- 用量按实际调用聚合，明确零与未知。没有价格依据时只显示 token 和调用数，不编造费用或缓存节省。多步任务保留逐步与整轮统计，避免重复计数。
- 用 fake provider 验证成功、超时、取消、鉴权失败、异常响应、缺失用量、配置切换与日志脱敏；真实付费测试单独报告。

以上是 Koyori 待实现方案，不声称参考项目已具备每一项保护，也不承诺首版支持全部协议、路由与预算系统。Provider 配置最终服务于一个真实 AI 功能；不为“AI Native”提前建设通用聊天平台。

## 不照搬的部分

- 参考项目公开文档不代表代码或素材可以直接复制；迁入实现前核对许可证与所有权，保留必要声明。
- Telegram Bot、群聊覆盖、PostgreSQL 租户与特定业务工具不进入 Koyori 默认模型。
- 个人持久 runner 执行 PR 代码的安排不适合直接作为公开贡献安全基线；Koyori PR 检查使用无秘密的隔离执行环境，签名发布另外隔离。
- 参考 CI 中以版本 tag 引用的 Actions 不直接照搬；Koyori 的发布基线要求固定完整 SHA 和最小权限。
- 不复制根 package.json 的全部依赖或版本；以最小工程验证桌面、站点和打包兼容性。

## 对起步顺序的影响

桌面壳、独立文档站、检查脚本、本地安装包与 Skills 管理切片已建立，当前证据见 [实施状态](../implementation-status.md)。接下来以个人 Agent 的文字会话和 Skills 建议引入 Provider；远端 Bot 接入先做独立设备身份与窄通道，按 [后端方案](backend.md) 验证后再挂到产品域名。公开发布仍需历史/产物检查、分发策略和候选产物验收。

这样借鉴的是成熟的交付方法，功能范围仍由 Koyori 的自用需求决定。
