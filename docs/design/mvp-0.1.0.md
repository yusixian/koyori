# Koyori 0.1：Skills 与个人 Agent 工作台

> 日期：2026-09-22 ｜ 状态：方向已确认，M1 工程起点与 M2 使用账本已实现；完整 0.1 尚未交付。
>
> 前一轮规划 goal 已完成；用户随后要求扩大首版，并明确希望加入个人 Agent、接入 cos-tool-bot。本稿替代此前“只读 Skills + 整理偏好”的窄范围，用户已批准开始实施及公开工程；生产部署与公开发行另按发布策略推进。以下均为目标，不是已实现功能。

## 1. 一句话目标

做一个自己愿意每天打开的 macOS 个人工作台：能整理 Claude Code / Codex 的 Skills，也能与一个有角色、记得明确偏好、连接现有 Bot 能力的 Agent 协作。从第一版就有正式品牌、文档站、版本和可下载安装包。

两条可独立使用、也能连起来的主流程：

1. **整理工具**：选择 Profile/目录 → 看资源与真实使用证据 → 查看建议 → 预览影响 → 保留、复查、受控整理 → 能恢复。
2. **和 Agent 一起工作**：连接模型或自己的 Bot → 文字对话 → 主动附上选定 Skills 与统计摘要 → 解释建议并生成操作卡 → 本机确认和执行 → 返回结果。

Skills 的扫描、统计、规则与整理不依赖 AI。Agent 有自己的原生界面，通过明确选择连接到 cos-tool-bot；服务器继续保存私有能力。语音参考 CosyVoice / ChatTTS 的表达体验，首版具体深度尚待选择。

## 3. 首版长什么样

### 导航与日常使用

左侧放“Agent、Skills、我的服务”，底部放连接/来源设置、文档和版本；记住上次页面。新增服务先支持名称、地址、图标与打开方式，Bot 是第一个真实接入目标。首页不堆尚无数据的仪表盘。

以下仅为结构草图；所有资源、次数与对话均为合成示例。

Skills 页面沿用同一工作台：中间是搜索/筛选和资源列表，右侧详情显示来源、客户端可见范围、使用证据与整理动作。“和 Agent 一起整理”把当前选择带进对话，发送前可预览；不会让 Agent 默默扫描所有项目。

纸白主面、轻樱粉选中态、少量薄荷强调；现有角色用于导航和真实工作状态，不用夸张动效占满界面。约 1200×800 设计，960×640 仍能完成流程，窄窗口详情可独立打开/返回。首版优先浅色完整体验，兼顾键盘、焦点和可读性。

### 首次使用与主要状态

1. 可先连接本机 Skills 或开始配置 Agent，两者不互相阻塞；示例模式显著标记，数据完全隔离。
2. 用户选择 Profile/资源根，历史读取另行选择；候选路径可改，不写死个人目录。
3. Agent 选择自配模型或个人 Bot 连接，明确数据发送到哪里；不要求注册 Koyori 云账户。
4. 扫描、导入和生成有进度、取消、错误与重试；展示上次有效结果及同步时间。
5. 统计区分“未连接历史”“数据不足”“覆盖内 0 次”；调用次数不由 AI 猜测。
6. 详情预览不执行 Skill 内脚本/HTML；远端界面不获得本机文件与 shell 权限。

## 4. 扩大后的范围

| 模块 | 0.1 建议交付 | 明确边界 |
| --- | --- | --- |
| Skills 资源 | Claude Code/Codex 多 Profile、可配置根、搜索筛选、来源/重名/共享链接、文本预览与变化刷新 | 静态发现不等于当前会话已加载；不把第三方的客户端数量当成自己的已验证支持 |
| Skills 管理 | 本地目录导入应用资源库、部署到选定项目、撤销受管部署、整理计划和恢复记录；独立外部目录的归档须通过边界验证 | 不接管 plugin 管理目录、不覆盖外部修改；共享源与未知依赖有明确提示，详见下节 |
| 使用账本 | 至少一个可靠客户端适配器，默认先验证 Claude；30/90 天次数、会话数、最近使用、覆盖/缺口；增量导入与去重 | Codex 首先保证资源清单；只有通过真实样本验证才显示明确调用数 |
| 规则整理 | 闲置/低频、复查到期、相同内容候选；始终保留、稍后复查、应用内定期摘要 | 规则可解释、阈值可改；低频不等于无用，mtime 不等于过期，建议不自动执行 |
| 个人 Agent | 原生文字对话、流式回复、停止/错误重试、独立会话、稳定角色、可管理的明确偏好 | 不做会话树、任意自主执行、多 Agent 调度、终端和完整聊天平台 |
| Agent × Skills | 选择上下文、解释统计/内容、引用证据、生成保留/复查/整理操作卡 | 本机白名单 + 当前计划确认；远端模型无通用写权限 |
| 模型与 Bot | 一种经验证的自配模型协议支持基础 Agent；个人 cos-tool-bot 通过专用接口提供真实桌面会话及一项获准服务能力 | 不复制 Bot 全部实现；连接切换不自动传递历史，不静默回退另一 Provider |
| 我的服务 | 手工登记服务、收藏与打开；Bot 管理后台提供入口 | 嵌入式 GUI 先做可行性实验；未通过登录/隔离验收则明确外部浏览器打开，不宣称已嵌入 |
| CLI | 共用核心的扫描/统计/规则查询及只读计划预览，结构化输出 | 不并发直写 GUI 数据库；首版执行在桌面授权，不先建后台服务协议 |
| 文档与发行 | 正式品牌、文档/下载/更新说明站点、Dokploy 部署准备、版本与 macOS 安装包、验收发布链 | 实际发布受授权和环境约束，不能以完成 CI 冒充安装包或生产验收 |

**语音待决**：候选为文字主流程 + 按需朗读；若要首版语音输入/打断，则另加 ASR、麦克风、音频生命周期与延迟验收。详见 [Agent 方案](personal-agent.md#2-cosyvoice--chattts-的参考边界)。目前不强制捆绑 CosyVoice/ChatTTS 代码或权重。

## 5. 整理必须真的可恢复

受管操作统一为“生成计划 → 显示来源与影响 → 用户确认 → 重新核对 revision/路径边界 → 留恢复材料 → 执行并回读”。AI 只能准备提案，不能替用户批准。

- 本地导入复制完整 Skill 目录到应用资源库，保留来源信息和内容摘要，不修改原件、不执行安装脚本。首版远程 Git/ZIP 导入后置，先把本地文件与目录边界做实。
- 向选定项目部署优先采用经客户端验证的链接或副本；生成冲突计划，已有不同内容不覆盖。“项目撤销”只移除 Koyori 登记且仍未变化的部署，不删除共享源；全局仍可见时如实显示。
- 对已有外部资源，首版只考虑用户选定、独立、非插件/非共享的普通 Skill 目录归档。完整目录移入本机恢复区，且验证归档区不在已登记的客户端扫描根中；不声称能控制未登记客户端。
- 共享源、未知链接、已知引用保护、目标冲突或无法安全归档时，给出原因并保留/复查，不能自动降级为强制移动。未发现静态引用也不证明无人依赖。
- 归档与恢复都检查原/目标位置和内容是否发生后续变化，冲突时暂停，不覆盖新文件。跨卷失败、权限失败、磁盘不足、中断和部分成功写入操作日志，恢复材料不是缓存。

首版不做后台自动更新用户 Skill、任意覆盖合并或永久删除。文件系统动作不因为数据库事务成功就被视为原子完成。

## 6. 统计与兼容性先验证

M0 用合成日志和用户选定的小段真实记录，人工比对手动调用、模型调用、失败、复制/分叉历史和子代理。记录客户端版本、支持事件与缺口；真实内容不入 Git、站点、公开日志或验收截图。

按原始事件身份去重，请求/结果关联更新同一事件；名称提及、资源描述注入、读取 SKILL.md 不计明确调用。资源身份与路径、名称、hash 分开，同名来源不自动合并，无法可靠关联的移动保留未知。

至少一个真实适配器通过核验才算账本完成；不能全是“未知”也宣称成功。若默认 Claude 方案不可行，核对另一适配器后明确调整计划，不绕过该要求。

Skills Manager 的目录映射、发现/部署规则与测试可作为参考和移植候选；Koyori 保持自己的领域模型、证据账本、界面和 Agent 主线。引入前固定上游 commit，挑具体文件，检查许可与依赖，移植后在 Koyori 的 macOS/Electron、可配置根和客户端版本上重新验证。它的管理活动记录不能当成客户端调用统计。

## 7. Agent 与私有 Bot 的分工

公开端放原生 UI、连接契约、本机权限和合成测试服务；Bot 的业务实现、私人提示词/数据、Provider 凭据和生图实现留在服务器。暂不把 Bot 作为 Koyori 的依赖包，未审阅的“可能可公开”代码仍不复制。

推荐在 Bot 内新增窄桌面通道，复用经过评估的服务器能力；独立设备配对、能力范围、桌面会话身份和撤销。已有 runs/debug 管理接口不足以直接作为完整个人 Agent，不能传任意 chatId 假扮 Telegram 用户，不能把后台管理员 token 塞进安装包。

基础 Agent 让其他开源用户能自配模型，功能仅覆盖文字、明确偏好及少量本地查询/提案；个人 Bot 模式用于接回既有服务。两者用相同的展示契约，不同时运行、不自动共享历史。具体协议、验证和记忆边界见 [接入草案](personal-agent.md)。

Bot 接入意味着未来需要该项目内的一组改动；本文只是规划，不授权现在修改参考仓库或生产。整体实施范围需同时列清桌面端与服务端的责任，不把新增服务端工作藏在“接个 API”里。

## 8. 工程起点

候选：pnpm workspace + TypeScript strict，Electron + React，electron-vite 构建、electron-builder 打包；文档沿用参考项目的 Fumadocs + React Router 预渲染。M1 验证依赖组合和原生模块打包后固定版本与锁文件。

```text
apps/desktop       主进程、窄 preload、React 工作台与 Agent 界面
apps/cli           只读查询与计划入口
apps/site          公开文档、下载与版本说明，独立 Dokploy 构建
packages/core      Skills 扫描/统计/规则/计划/执行和持久数据
packages/agent     实际需要时建立的连接适配、事件与受限工具契约
docs/releases      发布正文唯一来源
acceptance         合成数据、流程检查与报告生成
```

不先建 plugin-sdk、账户、商业化或空抽象包。一个能力只有一份实现，GUI/CLI/AI 通过同一核心；桌面主进程协调持久写入，耗时扫描/解析移出 renderer 和主进程关键路径。

SQLite 是持久数据候选，驱动先过 Electron 打包。设置、偏好、最小调用事件、操作记录和恢复材料不能因清缓存丢失。Agent 会话的本地缓存与远端权威历史明确区分，密钥仅用系统安全存储；保存导出与可公开报告是两种操作。

本地核心无需账户或网络；AI 发送选定信息前可预览，默认不上传会话原文。链接跨已授权根不跟读。公开 fixture 使用虚构路径/项目；日志和诊断脱敏。远端网页无 Node/通用 IPC，限制导航与权限，不关闭 webSecurity 换兼容性。

## 9. 文档站、版本与分发

| 页面 | 首版内容 |
| --- | --- |
| `/` | 定位、成熟度、真实截图、当前可用版本与入口 |
| `/docs` | 安装、首次扫描、计数口径、整理/恢复、Agent/模型/Bot 连接、数据去向、排障与贡献 |
| `/download` | 版本、架构、最低系统、签名状态、DMG/ZIP、SHA-256 和历史入口；无产物时显示未发布 |
| `/changelog` | 从 docs/releases/v*.md 生成，包含变化、迁移、限制与验证范围 |
| 安全/许可 | 真实可用的私密报告渠道、代码与品牌许可、第三方完整声明和来源映射 |

Dokploy 只部署独立站点镜像，不包含用户数据、Bot 服务端源码或密钥。安装包放公开 GitHub Releases，站点使用发布清单；应用显示产品 SemVer 与可追溯 commit。README 如实区分“参考”和“实际使用/改编”，代码引入时同步安装包中的第三方声明。

默认首发 macOS Apple Silicon DMG/ZIP；最低系统随实际 Electron 版本验证，Intel 等有真实验收环境再加入。版本从首个有用切片 `0.1.0-alpha.1` 开始，后续 alpha 逐步补齐本稿范围，**整个扩大版完成后才称为 0.1 MVP**。不把缺功能的 alpha 宣称全量完成。

每个 alpha 具备可用功能、文档和安装包，不为桌面空壳发公开版。首版有手动检查版本/读说明/下载；自动下载安装在签名、公证和真实升级路径验证后开放。

发布流程：固定 SHA/版本 → 构建与签名 → 验收同一产物 → 上传校验 → 公开 Release → 更新站点/渠道 → 验证公网。详见 [发布基线](release-foundation.md)。环境或发布授权缺失时保留未完成项，不重新构建未经检验的包替换候选。

## 10. 里程碑与 Sol 分工

用户已批准开始第一个工程里程碑。里程碑用于缩小每次开发/验收范围，不代表删掉用户要求的扩大版范围，也不承诺日历工期。

| 阶段 | 可以看到的结果 | Sol 的有界任务 | 主代理退出检查 |
| --- | --- | --- | --- |
| M0：两条主线验证 | 一个可靠 Skill 事件样本、Bot 接入/身份方案、语音选择 | 单日志适配器试验；合成协议样本与指定接口调研 | 人工核对次数，确定 Bot 服务端改动、第一项远端能力和语音边界；不可行项调整方案 |
| M1：桌面与交付骨架 | 带品牌/版本的工作台、示例页面、文档预览、本地包 | renderer 基础；独立站点骨架 | 工具链、IPC、数据与公开代码边界，干净环境构建/安装 |
| M2：Skills 首个可用切片 | 双客户端清单、单客户端账本、规则/偏好、只读 CLI | 扫描器/适配器/规则分别派工，契约稳定后做 UI | 真实资源与计数，未知状态、取消、重启持久化；可作为首个 alpha 候选 |
| M3：可恢复管理 | 本地导入、项目部署/撤销、计划/归档/恢复 | 核心单动作及临时目录故障用例；对应 UI | 外部编辑冲突、链接边界、中断和恢复；不损坏原数据 |
| M4：个人 Agent 与 Bot | 原生对话、明确偏好、基础 Provider、真实 Bot 桌面会话、一项获准能力 | 分配连接适配、会话 UI；Bot 改动在该项目独立任务/分支 | 配对/撤销、流式/取消/重连、私有字段过滤、真实远端行为 |
| M5：两条主线连起来 | 选择 Skills 讨论、证据引用、操作卡；若纳入则完成朗读/语音 | 受限工具适配、操作卡组件、选定音频模块 | 本机授权不被远端绕过，记忆/上下文可解释；首版语音边界真实验收 |
| M6：扩大版 0.1 验收 | 完整文档、候选安装包、真实自用流程和发布证据 | 有界修复、公开指南、发布页面/脚本 | CI、安装/升级、开源检查和授权发行；核验线上站点及产物 |

实施按用户指定使用 `sol_worker`，不默认换成 Luna。派工附目标、接口、文件所有权和验收条件，说明共用工作树、禁止回退他人改动。主代理负责架构/审美、共享契约/根工具链、代码审查、集成、最终测试与提交/部署/发布；Sol 不可用时主代理继续并说明。

只并行无共享写入且契约已明确的任务，不把整个 MVP 一股脑交给子代理。

## 11. 完成与测试标准

| 范围 | 必要证据 |
| --- | --- |
| 资源/计数 | 多根、同名、共享链接、损坏/截断日志、重复历史与请求/调用区分；真实小样本计数与人工一致 |
| 只读保护 | 扫描/统计/偏好不改变原 Skill 或配置；CLI/GUI 核心查询一致 |
| 文件操作 | 临时目录验证修改冲突、中断、跨边界拒绝、部分失败与恢复冲突；真实操作只在用户选定范围 |
| Agent | 合成服务覆盖流式、错误、取消、重连/幂等、设备撤销和会话隔离；真实 Bot 流程单独记录，不能用 mock 冒充 |
| 本地授权 | 越权/过期/篡改提案拒绝，确认后的内容或文件变化使计划失效；技能文字、模型建议不授予权限 |
| 记忆/隐私 | 查看/修改/遗忘有效，切换连接不泄漏历史；不提交真实对话/密钥；私有服务代码不进入公开包 |
| UI/语音 | 首次、空/加载/取消/错误、详情返回、窄窗口/键盘；若选语音，停止后不播放旧音频，文字仍可用 |
| 质量/产物 | 真实配置的 lint/类型/相关测试/构建通过，全量 CI 完成；安装/启动/版本/SHA/重开/升级数据验证 |
| 站点/发布 | 深链、搜索、移动导航、404、版本/下载；公开后验证实际产物和线上版本，许可与发布证据齐全 |

日常只做相关检查，全量交 CI；不追覆盖率或为文档跑应用测试。性能先用约 200 个合成 Skill 与 10,000 条事件观察交互和取消响应，记录机器/耗时再设阈值。

公开源码前检查拟公开历史/文档/附件；选定代码许可证、品牌范围和报告渠道。先记录一次真实自用反馈，代理不代答满意度，不编造连续使用天数。

## 12. 取舍、风险与回退

| 方案 | 好处 | 代价 / 结论 |
| --- | --- | --- |
| 只读 Skills 窄版 | 最快验证计数与发布 | 用户认为不足，本稿扩大 |
| Skills + 原生个人 Agent（推荐） | 对应资源整理与 Bot 入口，两者有具体联系 | 写入安全、服务端改造和鉴权变复杂，按 M0–M6 分段验证 |
| 先复制完整资源管理器 / Bot | 表面功能齐全 | 定位、私有代码、兼容和依赖边界失控，不采用 |

主要风险是日志归因不可靠、外部资源写入冲突、Bot 入口依赖 Telegram 身份/投递、私有实现混入公开包、语音许可/算力不明和桌面签名尚未准备。分别以样本门槛、操作日志/恢复、独立桌面通道、显式公开文件范围、语音选择与提前打包解决，不把风险藏在收尾阶段。

导入失败可去重重跑，坏批次不覆盖有效账本；持久迁移先备份；文件恢复检查外部变化。连接可撤销，Bot 桌面通道可关闭，本地 Skills 与原 Telegram 入口独立。发版失败不推广新渠道，坏版本用新版本修复，不覆盖原包；应用降级不意味着数据库可直接降级。

## 13. 审阅与未来 goal

这次需要过目的核心是：**首版成为“Skills + 个人 Agent”工作台；Bot 通过服务端接口接入，私有实现保留；按多次 alpha 完成一个更完整的 0.1。** 语音深度和第一项远端能力在 M0 前确定，具体界面通过第一轮原型继续收敛。

域名/Dokploy 目标在部署前提供，许可证/品牌与私密报告渠道在公开前决定，签名在发行验收前落实。缺签名只可按明确限制做手动 preview。整体批准实现不自动授权改仓库可见性或上线生产；有持续发布策略后按策略直接推进，不重复索取已有授权。

未来实施 goal 候选：

> 交付 Koyori 0.1 自用个人工作台：Claude Code/Codex Skills 清单、至少一个客户端的可追溯使用账本、可解释规则及可恢复管理；原生个人 Agent、基础模型连接、明确偏好与 Skills 操作卡；以不公开私有实现的方式完成 cos-tool-bot 桌面通道及一项获准能力。配套 Dokploy 文档站、版本/开源基线与验收安装包。语音以用户选定范围为准。主代理集成验证，Sol subagent 编写有界模块；按获准范围开展跨仓库改造，环境与发布授权具备后完成 preview/0.1 分发并核验，未完成项如实保留。
