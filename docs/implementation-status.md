### 个人 Agent（当时开发版）

- 支持用户配置 OpenAI-compatible Chat Completions 流式连接；连接配置按连接身份隔离，API 密钥使用系统安全存储，不在界面回显。
- 启动和浏览会话不访问钥匙串；仅明确保存非空密钥或使用已存密钥发送消息时才探测，取消授权不降级为明文。
- 本地会话支持新建、切换、改名和删除；发送后逐段显示文字，支持取消。失败、取消和应用退出中断会保留对应状态，服务没有返回 token 用量时保持未知。
- 请求只携带当前会话文字，不自动发送 Skills、使用账本、目录或日志；当前 Agent 以纯文本回复为主，没有本机写入工具。
- Bot 桌面通道/API、工具操作卡、语音和正式 0.1 仍未实现；后端参考方案见 [后端与统一域名](design/backend.md)，不把私有 Bot 实现带入公开工程。

### 我的服务（当时开发版）

- 可登记名称和 HTTPS 或本机回环 HTTP 地址，并查看、修改、移除；服务设置仅保存在本机。
- 打开动作仅接受已登记服务 ID，主进程重新校验地址后交给系统默认浏览器。Electron 继续禁止远程导航和新窗口，外部网页不嵌入应用，也不获得 IPC。
- 保存不探测地址或调用服务 API。拒绝非回环 HTTP、URL 凭据、查询参数和片段；当前没有 Bot 配对、远程工具或 Koyori 云 API。
- 无效设置不会覆盖原文件；写入前保留备份，错误显示可检查的数据目录或恢复文件信息。

### Skills → Agent 单 Skill 讨论（当时开发版）

- 用户从资源清单选择一项 Skill 后，主进程按选定观察窗口生成完整预览；白名单摘要只包含名称、客户端、观察窗口、次数及证据缺口、保留/复查状态和规则类型。
- 用户审阅摘要后，可将它追加到当前可编辑草稿并手动发送；已有草稿保留，加入前可丢弃摘要，加入后可在草稿中删除，准备摘要不会自动请求模型。
- 摘要不包含 Skill 正文、描述、路径、原始会话或其他资源信息。名称可能私密，发送前由用户审阅；统计快照不会随账本变化自动更新，未知、同名待归属和暂停状态仍解释。
- 当前只支持单 Skill，不支持多选、全文附件或证据引用跳转。讨论摘要本身没有执行权限；本机可另行选择“始终保留”或“30 天后复查”操作卡，预览并确认后才写入偏好。PR #5 的测试不作为本轮新功能的验收证据。

### Skills 发现与清单

- 启动时自动检测 Claude Code 配置目录下的 `skills`、Codex 的 `~/.agents/skills` 与兼容 `$CODEX_HOME/skills`；运行期间每 30 秒刷新。
- 只检查用户目录和明确登记项目中的 `.claude/skills`、`.agents/skills`，不搜索整块磁盘。`/etc/codex/skills` 只读。
- 规范路径去重，识别共享目录和链接；缺失但可写的客户端目录只作为同步目标候选，不因发现而创建。
- 自动发现可以暂停；移除来源会记住忽略状态，原目录不删除，也不会立即被下一次扫描重新接回。
- 自定义目录、项目登记、搜索、客户端筛选、纯文本预览和可取消扫描继续保留。

### 使用证据与整理建议

- 自动发现 Claude Code 历史候选，但默认不读取；用户选择并开启后立即检查，启动补扫并随 30 秒刷新周期继续更新。
- 未变化的日志复用本地增量缓存；新增或变化文件重新解析，事件按稳定身份去重，后出现的结果补齐原事件。缓存可重建，账本仍是权威持久数据。
- 调用尝试、成功返回、失败、结果未知与显式请求分开；文本提及、资源注入和读取 `SKILL.md` 不算调用。
- 显示实际覆盖、版本、坏行、跳过和读取上限；Codex 会话目录可被发现，但当前不支持调用统计，不显示虚假零调用。
- 保留、稍后复查、到期提醒、相同内容与闲置/低频候选继续使用证据门槛；“未观察到”只触发有依据的复查，不等于可以删除。

### 同步、本地备份与恢复

- Claude Code 与 Codex 之间采用完整 Skill 目录复制，包含脚本、引用和素材，保留文件执行位，不修改来源原件，也不运行目录内脚本。
- 同内容目标跳过；不同内容默认冲突。替换必须明确选择并重新生成计划，执行前再次核对来源、目标 revision、真实路径与授权根。
- 目录链接只有解析到已授权根内才会读取；内部链接复制为实际内容，跨界和循环链接拒绝。目标链接不会被静默接管。
- 手动备份保存完整本地快照；替换前自动保存写前快照。恢复也先预览，外部编辑会使计划失效。
- 多项恢复逐项记录成功、失败、取消与进程中断；运行中进程退出后，日志会在下次启动标记为中断，不把部分成功写成全部完成。
- 替换保留实际被移走的原目录；最后校验后出现外部编辑会回滚并报失败。最近文件操作展示恢复材料路径；中断后按记录人工核对，不自动覆盖目标。
- 便携快照去掉原位置与本机真实路径，只保留目录名、内容、相对 manifest 和摘要。导入后必须选择恢复客户端，不能猜测原路径。
- Git 远端连接、完整快照上传、提交核验、历史取回和受选定资源范围限制的自动备份已接入桌面。隔离 bare Git 仓库往返通过；真实外部账号未验证。私有仓库使用已配置的 SSH 身份，HTTPS 当前仅支持无需认证的远端。

桌面与 CLI 共用核心计划。CLI 已加入 `discover`、`sync`、`backup`、`backups` 和 `restore`；`sync` / `restore` 先输出计划与 revision，只有使用相同选项附带 `--apply <revision>` 并通过重新核对后才执行。

用户指南见 [Skills 发现、同步与备份](../apps/site/content/docs/skills-management.mdx) 与 [Skills 使用统计](../apps/site/content/docs/skill-usage.mdx)。内部口径见 [账本实现](design/usage-ledger.md)。

## 真实 Git 远端备份手工验收清单（待执行）

此清单供维护者在真实账号环境逐项执行；目前没有真实外部账号的通过结果。操作入口与状态含义见 [Skills 备份指南](../apps/site/content/docs/skills-management.mdx#保存到-git-远端)。只用合成 Skill 和专用私有测试仓库，记录结果时不要公开仓库地址、用户名、密钥或 Skill 内容。

- [ ] **前提与隔离**：使用独立 macOS 测试账号，在该账号由 Koyori 检测到的 Claude Code Skills 目录准备不含真实凭据的测试 Skill（包括可辨认的文本文件，按需加入空目录或执行位文件），记录文件摘要；确认该账号的 Codex Skills 目标没有同名目录且可写。不要使用日常账号，即使另设 Koyori 数据目录也仍可能扫描或恢复到日常客户端目录。确认该账号下 Git 可用、网络可达，并准备仅用于本次验收的空私有仓库；不要把现有备份库改绑新远端。
- [ ] **账号与地址**：为该私有仓库配置具有读写权限的 SSH 身份，并在测试账号中运行 `GIT_CONFIG_GLOBAL=/dev/null GIT_CONFIG_NOSYSTEM=1 GIT_TERMINAL_PROMPT=0 GIT_ASKPASS= git ls-remote git@github.com:OWNER/REPO.git`（将示例地址换成测试仓库 SSH 地址）预检读取权限。Koyori 不读取 Git 全局/系统配置，也不提供交互提示；SSH 身份需在 `~/.ssh/config` 或该账号的 SSH agent 中可用，不能只依赖 shell 启动配置。从“应用程序”启动 Koyori，仍以应用内连接和上传结果为准。在 Koyori 中只填 SSH 仓库地址，不要把密码、Token、私钥写进 URL、Skill 或验收记录；当前 HTTPS 只支持无需认证的远端。
- [ ] **上传核对**：在“同步与备份”创建仅含测试 Skill 的本地快照，连接仓库、选择该快照，检查目录内容并显式同意上传。记录界面显示的快照时间和资源数、“远端已核验”状态及提交摘要；用仓库服务的私有页面或独立 Git 读取核对 `koyori-backups` 分支提交与摘要一致，并确认没有其他 Skill 文件。
- [ ] **取回核对**：从“远端历史”选择刚上传的提交并取回；确认生成本地快照而未直接覆盖客户端目录。选择该测试账号的 Codex Skills 作为恢复目标，确认计划对测试 Skill 是复制而非跳过，再执行恢复；逐项比较恢复文件与原 Claude Code 测试 Skill 的字节摘要、目录结构和可执行权限，并确认原来源未被修改。
- [ ] **失败与恢复**：修改合成测试 Skill 并创建第二份本地快照，在仍保留两份快照的前提下，用可撤销的网络断开或临时失效的 SSH 权限触发这份新快照上传失败；确认界面报告失败、本地快照仍可用，恢复连接或权限后重试同一快照并重新核对远端提交。若远端有不同历史，应停止并调查，不强制推送、不删除原仓库或本地恢复材料。断开远端后确认本地快照仍可恢复。
- [ ] **收尾与记录**：在私有验收记录中填写测试日期、应用版本与安装包来源、测试环境、仓库权限、每步结果、提交摘要和失败恢复观察；清理测试数据前确认所需恢复材料已保留。任一步失败或无法核对时记录“未通过/未验证”，不要把隔离 bare 仓库证据当作真实账号通过。
