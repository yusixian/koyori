# Koyori 实施状态

> 2026-09-22；工程起点已实现，尚无公开发行版。产品已定名 Koyori · こより，公开仓库为 [yusixian/koyori](https://github.com/yusixian/koyori)。

## 当前 goal

完成扩大版 0.1 的工程起点：公开源码与 MIT/品牌/第三方声明，macOS Electron 工作台、可配置目录的 Claude Code/Codex 只读 Skills 清单、共用 CLI、独立文档站、唯一版本源、无秘密的隔离 CI 与本地候选安装包。Sol 分别编写扫描核心与文档站，主代理负责架构、桌面权限、集成与最终验证。

语音、调用账本、可恢复整理、真实个人 Agent 和 Bot 服务端接入仍属于完整 0.1 后续里程碑；它们没有因本次工程起点完成而被视为交付。不修改私有 Bot，不部署生产站点，不公开发行安装包。

## 工程当前能力

- 主动选择客户端/目录，来源设置本机保存；移除来源不删除原文件。
- 只读扫描、搜索、客户端筛选、纯文本预览、缺失/损坏/越界提示；扫描运行在独立 worker，可取消。
- 示例数据与真实目录分离；尚未采集使用情况，不显示虚假的零调用。
- CLI 与桌面调用相同核心。Agent/服务页面明确标记为尚未接入。
- 公开文档只构建指定内容目录，下载页在没有 Release 时不提供假链接。
- 本地候选产物记录版本、构建 commit、工作区是否修改和 SHA-256；默认未签名、未公证。

文档站以生产静态产物验收桌面/移动导航、文档深链、搜索、更新说明与无发行版状态。CI 会在独立 Linux 环境执行文档容器构建、健康检查和 404 检查，并在 macOS 构建后再次启动实际应用；具体 commit 的远端结果见 [GitHub Actions](https://github.com/yusixian/koyori/actions)。

本机未启动 Docker daemon，容器行为交 CI 核验；尚未部署 Dokploy、签名、公证或验证跨公开版本升级。当前本地候选只覆盖 Apple Silicon macOS，不代表完整 0.1 或生产服务接入已验收。

## 后续顺序

1. 验证至少一个真实客户端的 Skill 调用事件，建立覆盖与未知状态的使用账本。
2. 引入受控计划、部署/归档及恢复，验证外部编辑与中断。
3. 原生 Agent 基础连接、会话与可管理偏好；在私有服务侧独立实现桌面通道。
4. 把选定 Skills、统计证据与操作卡串起来；语音依选定边界加入。
5. 完成扩大版验收后按授权发 preview，再逐步完成 0.1；文档和分发与功能同步。
