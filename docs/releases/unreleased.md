# 未发布

当前开发版本：以根 `package.json` 为准。尚无公开发行安装包。

## Skills 自动发现与清单

- 启动和运行期间检测 Claude Code、Codex 的用户级已知目录；支持登记项目后发现项目级 Skills。
- 支持 `CLAUDE_CONFIG_DIR`、`CODEX_HOME`、`~/.agents/skills` 与 Codex 兼容目录；系统目录保持只读。
- 规范路径去重，识别共享来源和链接；自动发现可暂停，移除后不会立即重新接回。
- 新增发现结果、目标候选和历史候选的持久设置；不会因为发现而创建、上传或执行内容。

## 同步、本地备份与恢复

- 在 Claude Code 与 Codex 之间预览并复制完整 Skill 目录，保留脚本、素材和文件执行位。
- 同内容跳过；不同内容默认冲突，明确选择替换后重新生成计划。执行前复核来源、目标 revision、真实路径和授权根。
- 替换前自动保存写前快照，也可手动备份选中 Skills；恢复继续检查外部编辑，并记录部分失败、取消和进程中断。
- 便携快照只包含相对 manifest、SHA-256 摘要和完整内容，不带原位置；导入后需要选择恢复客户端。
- CLI 新增 `discover`、`sync`、`backup`、`backups`、`restore`。同步和恢复先输出计划 revision，再以同样参数显式 `--apply`。

替换时保留实际被移走的原目录；并发编辑导致的失败与进程中断均留下操作记录和恢复路径。本地快照不代表内容已经上传。

## Skills 使用证据与整理偏好

Skills 提供“资源清单 / 使用与建议”视图。Claude Code 历史目录会作为候选显示，用户选择并开启后，应用启动补扫并在运行期间定期更新近 30 / 90 天统计。

- 分开呈现调用尝试、成功返回、失败、结果未知和显式请求；复制日志去重，后续结果补齐。
- 未变化日志复用可重建缓存，新增或变化文件重新解析；账本继续保留覆盖、坏行、读取限制和未归因事件。
- 始终保留、稍后复查、可调整规则、相同内容及闲置/低频候选；建议不会自动移动或删除。
- Codex 当前只支持资源盘点；会话目录即使被发现也不会启用调用统计，未采集状态保持未知。

## 自配模型 Agent

- 开发版支持用户配置 OpenAI-compatible Chat Completions 连接；连接设置按身份隔离，API 密钥使用系统安全存储。
- 支持本地会话新建、切换、改名、删除，流式文字回复、取消、错误/中断状态，以及服务报告或未知的 token 用量。
- 请求只发送当前会话文字，不自动附加 Skills、使用账本、目录或日志；当前没有本机写入工具、工具操作卡或 Bot 通道。
- 应用启动与浏览会话不访问钥匙串，仅在主动保存或使用密钥时访问；无需密钥的本机服务可独立使用。

## Skills → Agent 单 Skill 讨论

- 从资源清单选择一项 Skill 后，主进程按观察窗口生成可预览的白名单摘要，包含名称、客户端、次数及证据缺口、保留/复查状态和规则类型。
- 用户先审阅，再把摘要加入当前可编辑草稿并手动发送；现有草稿内容保留，加入前可丢弃摘要，加入后可在草稿中删除，准备摘要不会自动请求模型。
- 摘要中的名称可能包含私密项目或组织信息，用户应先审阅；摘要不包含 Skill 正文、描述、路径、原始会话或其他资源信息。统计快照不会自动变化，未知、同名待归属和暂停状态仍会解释。
- 当前只支持单 Skill，不支持多选、全文附件或证据引用跳转；整理建议没有操作卡和执行权限。

## 工程基线

已有 macOS Electron 工作台、共享核心与 CLI、独立文档站和隔离 CI；唯一产品版本、本地 DMG/ZIP 候选、摘要与打包后验收入口已经建立。文档站已配置独立 Dokploy 应用，正式域名 DNS/HTTPS 已实测，具体部署版本与验收单独记录。

个人 Bot 服务、桌面通道/API、工具操作卡、语音和自动更新尚未接入；文档站部署与桌面应用发行分别验收。安装包仍是本地未签名候选；完整 0.1 的剩余范围与验证分层见 [实施状态](https://github.com/yusixian/koyori/blob/main/docs/implementation-status.md)。

## Git 远端快照

- 连接自己的备份仓库，明确选择快照后上传；推送后核对远端提交，区分本地保存和远端已核验。
- 获取历史并取回便携快照，再选择客户端预览恢复；不直接覆盖本机目录。
- 自动备份默认关闭，仅监听用户选定的资源，变更后延迟保存，失败保留本地快照并重试。
- 不上传客户端会话、使用账本或本机路径配置；Skill 文件中自行写入的敏感信息仍需用户检查。
