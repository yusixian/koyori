## 长期能力演进（不替代首版里程碑）

0. 工程与发布基线：最小桌面壳、唯一版本源、检查脚本与 CI、Dokploy 文档站、下载和更新说明、本地安装包；已有公开 Preview，正式 0.1 的签名、公证及产物验收仍按发布门槛执行。与第一条功能切片同步建设。
1. 资源基础：Electron、基础 CLI、Skills 自动发现、预览搜索、来源与作用域；Claude Code 使用证据先行，Codex 在没有可靠适配器时保持未知。
2. 自用闭环：完整 Skill 目录同步、本地快照、恢复、便携导入导出与 Git 备份；配套闲置/到期复查、整理建议和保留偏好。MCP、commands 与缓存管理按真实自用需求后续加入。
3. 持续 preview：复用现有安装包、文档与发布链，完善反馈、社区及更新入口。更新能力按对应版本的签名与升级验收记录判断，不把开发模式启动当作安装包验收。
4. AI 增强：首个自配模型文字 Agent 已进入开发版；单 Skill 证据讨论已实现，后续先推进本地工具操作卡，再按独立授权接入私有 Bot 桌面通道/API 和语音，再评估 ACP、更多协议、提示词优化和更丰富的工作台工具。
5. 效果与自动规则：相同任务试验、任务预设、经授权的受限自动应用。
6. 商业验证：个人专业能力、可选云服务、团队共享；根据真实需求选择，不提前建设。

不频繁跑全套测试，不追求覆盖率。里程碑做相关类型/构建和真实流程检查；修改写入/删除/恢复边界时做针对性验证。前期不维护多代内部兼容，但真实资源和应用持久数据始终受保护。

[Skills 使用统计与整理建议](skill-lifecycle.md) 按“本地账本 → 可解释规则 → AI 顾问”推进。扩大版 0.1 提议同时包含机械提醒与按需 AI 解释；第 5 阶段的自动规则指经授权执行操作，不是基础定期检查。候选阈值和调用归因须经样本验证，不承诺完整历史总量。

## 产品标配

- 反馈入口：Issue 模板或表单，诊断摘要先预览，默认不包含项目内容和会话。
- 社区：先链接 GitHub Discussions；私有代码需要对外反馈时可另建公开 community 仓库。
- 更新日志：官网与应用引用同一发布内容。
- 更新：手动/后台检查，preview/stable 渠道，下载与错误状态；安装更新前等待配置写入完成，Agent 任务结束或明确停止后再重启。
- CLI：基础查询/扫描/计划与 MVP 同步，后续补齐已验证的执行接口。AI 不通过另一套逻辑改配置。

## 官网和分发

同一个 monorepo，apps/site 使用 React Router 与 Fumadocs 独立构建，已部署到 Dokploy，承载官网、/docs、/download、/changelog 及反馈/社区入口。正式域名 `https://koyori.cosine.ren/` 的 DNS/HTTPS、健康、深链和不存在路径检查已通过；部署 commit 与验证分层见 [实施状态](implementation-status.md)；工程约束见 [发布与开源基线](design/release-foundation.md)。

产品域名同时预留 `/api/v1` 服务入口。后端按[后端与统一域名](design/backend.md)参考职责分层、公共契约与独立发布边界；首个远端流程候选为私有 Bot 的独立桌面通道，自有云业务出现后再增加 Koyori API 服务。站点和服务独立发布，本地 Skills 不依赖服务器；当前只部署文档站，API 尚未实现，不复制私有 Bot 实现。

Preview 安装产物已通过公开 GitHub Releases 分发，需要时可扩展对象存储/CDN，不进入站点镜像或临时构建目录。代码已采用 MIT；正式发行仍需核对对应历史和产物，分发源不得要求客户端持有私有仓库 Token。下载/更新子域可固定入口，底层可替换。

打包器/updater 配套选择；参考 Lody 的 tag 版本统一、签名凭据隔离、原生平台构建和产物元数据匹配，不照搬完整 CI。当前 Preview 使用 Apple Development 签名且未公证；正式分发须另行完成 Developer ID、公证和对应更新路径验收。先构建实际支持的 macOS 架构。

发布顺序：不可变产物 → 下载与签名检查 → 更新渠道元数据。保持旧下载入口，能够停止坏版本分发；站点回滚不代表客户端/数据库可降级。CI 和 Dokploy 的外部动作在实施时按用户授权执行。

## 商业与开源

候选收费价值：个人高级自动化/评测，云同步/托管历史，团队共享规则/审核/审计。基础本地访问、导出、恢复和清缓存建议保持可用；不因订阅失效删除资源。

借鉴 Lody 的客户端与托管服务边界。未来计费/账户后端需要独立权限时另建私有服务仓库，公共契约连接；本地核心不依赖其存在。

已确定从首版开源，代码采用 MIT；品牌使用范围、买断/订阅与具体套餐尚未决定。当前不增加登录、遥测、支付、云数据库或 CRDT。
